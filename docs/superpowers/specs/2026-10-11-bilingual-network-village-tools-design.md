# Network 模板：双语后台、村庄管理与公开工具库

日期：2026-10-11

状态：用户于 2026-10-11 确认本设计，并指定由当前会话继续；详细实施计划仍需书面核对，尚未修改产品代码。

范围：独立的可复用 Network 模板；不修改原主站、私人后台或正式存储，不部署、不上传 GitHub、不调整托管、DNS 或 SSL。

## 1. 给项目负责人的简要说明

完成后，其他团队可自行部署模板，用自己的受邀邮箱账号运营自己的项目，不需要 ChatGPT 账号。居民不需要注册。

- 登录、验证器、工作台、表单、提示、匹配结果、打印卡和帮助说明均可切换中文 / English。
- 项目管理员可以单独授权某位负责人“允许新增村庄”，而不是把所有账号变成总管理员。
- 获授权者能新增村庄并管理该村；不能因此获得其他村的居民资料。
- 新村默认筹备中，名称和设置存进数据库。改名不改变编号，停用不删除历史资料。
- “模板与工具 / Templates & Tools”提供原项目公开通用模板、复制工具包和纸质工具。公众及后台均有入口。
- “操作指南 / Operations Guide”说明加村、邀请、登记、匹配、确认、权限复核和备份的步骤。服务器购买、续费和扩容仍在部署方的托管平台办理。

本设计不代表正式运营验收，也不代表已公开开源。实施后先给本地预览和测试结果。

## 2. 已确认的意图与边界

用户希望把独立 Network 模板交给其他团队复用，让他们能读懂、操作并扩展服务村庄。双语不是两套数据库，也不是运行时机器翻译。

已确认选择：管理员单独授权新增村庄；新增者仅得到自己的新村管理权限；普通负责人保持原授权范围；新村筹备、停用留档；公开页面与后台均提供工具库。

保持原米白、深绿、档案式字体与组件方向。不更换现有业务流程；匹配仅推荐，不自动接单，现场核实、本人同意、主备确认、费用与回访仍分别记录。

不纳入：公开注册、自动邮件、居民账号、定位、支付、第三方追踪、任意文件上传、CSV 批量入库、一键覆盖恢复数据库、医疗机构信息更新或新医疗建议。不会将既有研究结果变成其他项目的成果。

## 4. 权限设计

沿用 `admin`、`coordinator`、`analyst`、`reviewer` 角色；新增显式权限字段，缺失默认无新增权。

- `projectAdmin`：仅 `admin` 可具有，负责整个实例的村庄与授权管理；不通过“刚好覆盖全部村庄”推断。
- `canCreateVillages`：管理员可授予经核实的 `admin` 或 `coordinator`，默认 false；不授予分析、投诉复核角色。
- `managedVillages`：该账号获准管理设置和邀请协调人的村 ID 列表。新村创建者获得新村的业务范围及受限管理范围，不获得项目级权限。
- `villages`：沿用业务数据授权范围；受限管理范围必须是其子集。
- 授权记录增加 `version`，更新必须提交原版本及核实依据。

只有项目管理员可以授予、取消新增权和项目级权限。受限管理者可在自己管理的村内邀请普通协调人；不能授予管理员、分析者、复核者、项目级权限或新增权，不能修改自己的授权或接管他人村庄。

新实例的首次核实 bootstrap 明确设置项目管理员身份。项目管理员邀请新的项目管理员时必须单独确认该权限；激活前重新检查邀请人的当前权限，激活时赋予当前注册表范围，而不是过时的种子列表。

新村创建同时给全部有效项目管理员增加该村范围，避免管理员创建新村后失去全项目治理能力。普通账号和仅覆盖原有村庄的受限管理员不会自动扩权。

生产环境对项目管理员、既有管理员、可新增村庄者及受限村管理者强制已验证 MFA；普通协调人仍沿用原规则。相应扩展非 admin 管理者的 MFA 设置入口，不能授予权限后却不给完成验证的途径。服务端每次请求读取当前授权，不能仅依赖隐藏按钮或 cookie 内旧角色。

新增权被取消后，不能继续创建；已有村的业务范围与受限管理范围不自动删除。管理员可另行缩减这些范围或完全停用账号，界面须清楚显示三者区别。缩减后使该账号会话失效，并记录恢复边界。不能撤销最后一个有效项目管理员或通过自改授权绕过限制。

## 5. 村庄注册表与数据流

### 5.1 持久事实源

在加密业务状态内增加版本化的村庄注册表元数据；已有 SQLite 容器、密钥、实例标识、原有记录 ID 和事务机制保留。

- `villageRegistryVersion = 1`，记录不可变的 `seedVillageIds` 与单调递增的 `registryRevision`。
- 村庄包含 `id`、`zh`、`en`、`state`、`capacity`、现有 `contact`、`version`、来源与必要的创建审计字段。
- `config/project.json` 的村庄只用于首次建立种子。运行中名称、状态和容量以数据库为准；源码文件不被网页改写。
- 每次启动验证实例、密钥、状态版本、种子 ID、唯一 ID、合法字段及所有村引用。已注册动态村不必出现在源码配置中。
- 已初始化项目不能通过改种子 ID、替换配置或重新初始化绕过迁移。异常保持拒绝写入，不清空数据。

共享注册表模块负责校验和投影。服务器端不再用静态 `serviceVillages` 验证运行中的邀请或业务对象。前端工作台仅用授权快照，工具库不需要读取私人村庄列表。

既有 `x-farm-project-version` 继续校验编译时项目配置，不将实时注册表或权限当成该摘要的一部分；新增村庄不会令所有页面版本失配。记录与授权并发另外用各自 version / registryRevision 检查。

### 5.2 新增村庄

界面填写中英文名称和核实说明；不要求负责人自己编造数据库编号。没有英文名时允许负责人自行填入同名或拼音，不自动机翻。

HTTP 层先核实当前会话和 MFA，不能在业务事务内等待异步认证。服务器生成 `v-` 加 UUID 的稳定 ID；在一个同步数据库事务中再次检查活跃授权、写入保护、名称重复、幂等 key 和注册表版本，然后新增村庄、赋予创建者范围、更新项目管理员范围及审计。

名称去首尾空白，每种语言 1–80 字符，拒绝控制字符。重复比较使用 NFKC 规范化、去首尾空白并统一英文大小写；中文或英文名与原村对应字段重名时拒绝，让负责人加上乡镇等区分信息，不覆盖原村。显示名称保留负责人确认的字形。村默认 `PREPARING`、容量 1、无公开联系人。

相同用户同一 key 的重试返回原结果，不重复建村；重试前仍检查当前新增权。网络失败保留输入和 key。过期版本提示刷新核对，不静默覆盖。

### 5.3 修改与停用

项目管理员或该村受限管理者可更新中英文名称、状态、容量（沿用每半天 1–10 单）及经过核实的设置。更新带 version；不能改 ID。

不提供物理删除村庄按钮。暂停或关闭阻止新的受理、预留和开工，不删除、不改写历史，不替代正在执行事项的安全收尾、验收、付款或投诉处理。未结事项可见并显示提醒；无法安全开放时保持筹备或暂停。

公开工具页只呈现静态资源，不将居民数据、名单、邀请码或管理状态混进资源 API。本轮不开放原有生产 `/public` 或 `/registration/*` 路由，不增加公开服务联系人采集功能。

## 6. 升级、恢复与审计

这次不自动迁移任何正式实例。提供受控的独立迁移命令，先做一致性备份，再停止业务写入，在部署方自己的验证副本上检查和执行。

旧状态先通过原种子 ID 检查；只给可核验的首次 bootstrap 管理员绑定项目级权限。没有可核验绑定的旧实例拒绝猜测管理员，需部署方经身份核实显式指定原有有效管理员。不会把所有范围内管理员自动升级。

迁移为单事务且可重复检查，加入注册表和权限字段，保留原记录与隐私边界；未知结构、缺少安全材料、迁移失败或原配置不一致时拒绝，不调用 provision。初始化、迁移和生产启动职责分开。

权限缩减写入独立恢复边界，重放仅限制权限，不从边界凭空恢复授权。界面授权提升必须由当前有效项目管理员再次明确确认。恢复旧备份时使用最新可信边界，清除会话、待用邀请及旧 MFA 材料，停用所有具有管理或新增权的账号，按既有核验恢复流程重新绑定；不能使用旧激活 claim 恢复更大的村范围或新增权。

恢复验证注册表引用完整性。旧备份缺少后来新增村的业务资料时明确报告备份时点，不制造丢失记录、不恢复过时授权、不覆盖原卷。保存最新备份仍由部署方负责。

审计只记录账号/对象编码、动作、版本、时间和最少核实依据；不写密码、邀请码、验证码、密钥、完整健康信息或联系资料。语言切换不记录为运营成果。

## 7. 双语与界面结构

使用完整的固定双语字典，不能运行时机器翻译。用户输入的姓名、说明、地址、现场依据不自动翻译或改写；村名使用注册表中的 zh/en。

- 工作台顶部保留中英切换，登录和 MFA 页面也可切换。
- 当前语言可用 URL 的 `lang=zh|en` 与只存语言的本机偏好保持；旧管理/激活 URL 继续可用。
- 切换不重新加载、退出或丢弃同一会话未提交的表单；权限变化、退出或账号变化仍照常清除私人视图，不能以保留输入绕过清理。
- 工作区身份比对包含账号、角色、权限版本和授权范围；切换语言不改变该身份。刷新发现授权改变或异步请求所属会话过期时，原联系资料、表单与打印视图不能继续显示。
- 修改 document.lang、页面标题、aria-label、校验文案、错误码说明、空状态、状态标签、任务标签与打印文案。错误状态保留语义错误码，在渲染时按当前语言显示；切换后不能留下上一语言的错误提示，登录错误仍保持泛化。
- 界面数字、费用、业务时间、期限与表单约束共用数据，不在两种语言里分别硬编码。时间继续采用 Asia/Shanghai，并向英文用户标明时区。
- 所有角色按权限看到对应入口；新侧栏项为“村庄与权限”“模板与工具”“操作指南”，沿用现有编号、组件和布局。
- 375px 不横向溢出；英文长标签换行，按钮触控区域至少 44px；键盘焦点、对话框返回焦点和读屏状态保留。
- 不增加装饰性动画；沿用减少动态效果规则。

## 9. 静态文件与开源包安全

获准资源放入独立资源目录，不复制整个原站 `project-assets`。静态服务器只服务清单中的确切路径，保留路径遍历、隐藏文件、symlink、扩展名和 Content-Type 检查，并设置下载文件名和 nosniff。

资源目录及生产构建中的二进制文件均按确切路径、字节数及原始 SHA-256 白名单验证；未知文件、替换后的未审核文件、宏格式、超出已批准大小或原始研究文件继续拒绝。不得把 DOCX/XLSX/PDF/PNG/PPTX 全目录或全扩展名放开，也不提供任意远程 URL 下载代理。

## 10. 操作指南与运维职责

提供中英文角色相关的步骤和可用入口：
